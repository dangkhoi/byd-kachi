Mapping icon dẫn đường: GMaps → cụm (AMAP) / HUD (CAN)

Một hướng rẽ GMaps được phân loại thành một Maneuver trung lập, rồi encode ra hai bảng icon khác nhau: AMAP NEW_ICON 0..28 cho cụm (toAmapIcon) và CAN 1..49 cho HUD (toHudIcon). 01

Vì sao 2 bảng icon

Cụm và HUD là 2 đường ra độc lập (xem doc kiến trúc). Cụm nhận icon qua broadcast AUTONAVI = bảng AMAP NEW_ICON (AmapService tự remap CAN nội bộ). HUD nhận icon ghi thẳng feature INSTRUMENT = bảng CAN turn-id. Trước 1.14 app bắn mã AMAP vào feature CAN → HUD lệch 1 nấc → lật trái↔phải. Từ 1.14: 2 encoder thuần từ 1 Maneuver.

Bất biến: toHudIcon(m) == TurnIdMapToCAN[ toAmapIcon(m) ] cho MỌI Maneuver (đã khoá bằng test bảng). Ngoại lệ duy nhất: vòng-xuyến-lối-ra-N dùng offset ROUNG_ABOUT_NUM (firmware tự tính CAN 25..34), không qua TurnIdMapToCAN.
AMAP cụm — NEW_ICON 0..28 (toAmapIcon) CAN HUD — turn-id 1..49 (toHudIcon) NEW thêm ở Track B (2026-08-14) FIX sửa 1.23

GMaps signal → Maneuver (chuỗi classifier)

GMaps noti KHÔNG cho mã maneuver trực tiếp — phải suy. NavNotificationListener.handle() thử theo thứ tự (ưu tiên cao → thấp), ra mã AMAP rồi fromAmapIcon → Maneuver:

06

Vòng xuyến + lối ra thứ N

VN đi bên phải (RHT) → vòng xuyến = roundabout-right = CCW = NEW_ICON 11 (vào) → CAN 13 (进入环岛). Số nhánh ra:

Tình huốngCụm (broadcast)HUD
Vòng xuyến, chưa biết lối raNEW_ICON 11 → CAN 13toHudIcon(ROUNDABOUT)=13
Vòng xuyến + lối ra N (1..10)NEW_ICON 11 + ROUNG_ABOUT_NUM=N → firmware CAN 25..341.25: ghi thẳng CAN 24+N (25..34) vào HUD (cả 2 họ) → thử hiện số nhánh (chưa verify)
Ra khỏi vòng xuyếnNEW_ICON 12 → CAN 24 (驶出环岛)toHudIcon(ROUNDABOUT_EXIT)=24

Parse số nhánh: NavFormat.roundaboutExit — "lối ra thứ 3" / "3rd exit" / "take the 2nd exit" → N. (AmapFrameBuilder: exit∈1..10 → ép NEW_ICON=11 + ROUNG_ABOUT_NUM=N.)
