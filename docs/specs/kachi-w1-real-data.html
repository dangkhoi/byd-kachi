3. Requirements

R1 — Registry-driven (cốt lõi). Telemetry + control là DATA (bảng đăng ký ở :core), KHÔNG hardcode từng cái. Thêm 1 thông tin/nút = thêm 1 dòng registry, không viết code mới. Đây là cách nối "tối đa" mà vẫn ≤500 LOC/file + test được.

R2 — HAL binding có tier. Mỗi id map tới 1 binding: named-method (cho path proven-ClusterNav) hoặc feature-id số (cho path Overdrive) theo kiểu resolveOrFallback("Nested.FIELD", numeric) — resolve field framework thật trước, số là fallback. rc sentinel -2147482648 (NOT_PROVISIONED) ⇒ đánh dấu "không có trên trim này".

R3 — Evidence tier hiện rõ, KHÔNG bịa. PROVEN dùng bình thường; OVERDRIVE (chưa kiểm xe) vẫn NỐI + hiện, nhưng gắn badge nhỏ "chưa kiểm trên xe" tới khi verify; off-car / đọc null / NOT_PROVISIONED ⇒ "—" + mờ. Không hiện số giả.

R4 — Widget TỐI ĐA (thông tin). Toàn bộ nhóm widget ở catalog §D1: vòng năng lượng, thẻ sạc, PM2.5/không khí, bảng lốp, dải khí hậu, đồng hồ tốc-độ/công-suất, thẻ sức khoẻ pin (SOH/cell V/nhiệt), trip-meter, dải trạng thái thân xe, dải an toàn (dây/điểm mù/radar), odometer/danh tính.

R5 — Nút điều khiển TỐI ĐA. Toàn bộ tile ở catalog §D2: khí hậu (AC/quạt/nhiệt/recirc/defrost/PM2.5/anion), tiện nghi (ghế mát-sưởi 3 mức/sưởi vô-lăng/nhớ ghế), thân xe (kính từng cửa +%/tất cả/vent, cốp, nóc, rèm, gập gương, khoá trẻ em, gạt-mưa bảo trì, tự-đóng-kính-khi-mưa), đèn (DRL/pha/ambient 31 màu + độ sáng/đèn trần), drive/năng lượng (chế độ lái/EV-HEV/giữ-pin/target-SOC/regen/lái/phanh/AVH/mặt-đường), sạc (giới hạn %/thông minh/sạc-ngay/sạc-không-dây), ADAS panel (15+ toggle), giải trí (xoay màn/camera 360/độ sáng/nhạc-cụm), cụm/HUD (chiếu cụm/HUD on-off-mode-brightness-angle).

4. Design — kiến trúc registry-driven

4.1 Thành phần

  • TelemetryRegistry (:core) — mỗi datum = TelemetrySpec(id, label, unit, domain, widgetKind, tier, bindingKey). Bao 8 domain của catalog §A.
  • ControlRegistry (:core, MỞ RỘNG) — ControlSpec(id, label, icon, kind∈{TOGGLE,STEP,COVER,SELECT,BUTTON}, domain, tier, args) — domain CHỈ để gom nhóm panel (KHÔNG gate). (Hiện có 20 ControlDef {TOGGLE,STEP}; mở lên toàn catalog §B + thêm kind COVER/SELECT/BUTTON.)
  • CarStatus (:core) — snapshot bất biến mọi field; null = chưa đọc/không có.
  • CarCapabilities (:core) — id nào WIRED + tier — UI badge/mờ theo đây.
  • HalBindingTable (:app) — id → read(dev) / write(dev,args)→rc. Proven = named-method; Overdrive = set(int[]{fid}, EventValue) với resolveOrFallback. Tái dùng BydHal.device/callNamedInt. Sentinel → unavailable.
  • CarDataAdapter/CarControlAdapter (:app) — implements port, route qua binding (KHÔNG gate).
  • CarStatusRepository (:app) — coroutine poll 2 nhịp → StateFlow<CarStatus>.
  • UI (:app) — renderer generic theo widgetKind / ControlKind; tier badge; màn Tuỳ biến chọn từ registry.
  • Media bridge (:app) — MediaSessionManager.getActiveSessions(notifListener) → w_media + transport thật.
  • AppContainer — thêm carData/carControl/carStatusFlow; on-car adapter thật, off-car adapter thật trả null ⇒ "—" (chốt OQ1, bỏ demo).
