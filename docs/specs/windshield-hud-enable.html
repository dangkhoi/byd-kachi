Context

Hai correction bắt buộc: (1) HUD vật lý của Seal là W-mode và đang ON, nên “bật lại switch” không phải lời giải; (2) AUTONAVI_STANDARD_BROADCAST_SEND → AmapService là canonical cluster path và không được loại bỏ chỉ vì Seal chưa mirror lên kính. Kết quả âm tính trước đây chỉ có nghĩa là current Seal conditions/payload chưa mở nhánh HUD.
Owner cross-vehicle evidence — 2026-08-06: trên một số loại HUD, khi trigger cùng navigation session lên cluster thì HUD tự hiện mũi tên + khoảng cách và chạy ổn; tên đường vẫn thiếu trên HUD dù cluster có tên đường. Trên Seal, cluster hiện đầy đủ nhưng HUD không hiện maneuver/distance. Đây là differential evidence để xếp ưu tiên giả thuyết, chưa thay cho exact model/ROM capture.

Đã chứng minh trên Seal

  • AmapService full broadcast render cluster icon + distance + road.
  • Field-test thêm cùng lúc ba chuỗi *_AUTO + ROUTE_REMAIN_TIME_STRING và distance hết kẹt -1; chưa isolate field nào trong bundle là individually necessary.
  • HUD config=1 W-mode, physical switch feedback=1/ON.
  • SET_DYNAMIC_NAVI_FUNCTION_STATUS_SET=1 đơn lẻ chưa làm HUD mirror.
  • Direct INSTRUMENT_* rc=0 đơn lẻ cũng chưa render HUD.

Đã biết từ biến thể khác

  • Cùng cluster navigation trigger có thể kéo HUD lên tự động.
  • Mirror path đủ maneuver + distance.
  • NEXT_ROAD_NAME lên cluster nhưng không được mirror sang HUD.
  • Vì vậy content source có thể vẫn là AmapService, với downstream branch/gate theo HUD/vehicle profile.

Khoảng trống thật

  • Seal thiếu field, session transition, source flag, setting/property hay profile condition nào?
  • AmapService phát song song HAL/CAN và sendInfo2(4, FlatBuffer NaviInfo); HUD variant nghe nhánh nào?
  • State builder hiện chỉ biết STOP/reset 10019/9, chưa model start-state.
  • Road name cần field khác, encoding khác hay direct pathname side-channel sau khi mirror active?

Design

4.1 Canonical AmapService → cluster/HUD mirror model

canonical/provenvariant mirror gateseparate road gap
Interpretation: “Amap broadcast không lên HUD trên Seal” không phủ định AmapService. Nó xác định một missing conditional branch between AmapService output and Seal HUD. Direct INSTRUMENT writes remain useful diagnostics/possible road side-channel only after the Amap mirror session is active.

4.2 Two milestones

M1 · HUD enabled

  • Canonical Amap frame still renders cluster.
  • Seal HUD changes maneuver left↔right and distance.
  • Stop/clear works and physical HUD stays on.
  • Road may remain explicitly unsupported.

M2 · HUD parity

  • Road name visible and changes with frame.
  • Exact source identified: Amap extra, FlatBuffer field or side-channel.
  • Encoding/budget/clear proven.
  • No full-parity claim before P8.

4.3 Release-safe diagnostics boundary

Main / release

  • RebindReceiver android:exported="false".
  • No TEST_* actions/handlers/classes in main/release.
  • Production contains only field-proven mirror gate + canonical Amap transport.
  • System/package/watchdog delivery covered by tests.

Release-signed vehicleTest only

  • src/vehicleTest receiver + manifest; frozen action com.byd.clusternav.VEHICLE_TEST_HUD_MIRROR; exported=true only with android.permission.DUMP.
  • First target gate proves adb shell holds DUMP. A separately built com.byd.clusternav.probesender APK (ordinary UID, non-platform key, no DUMP) sends the same explicit Intent; denial plus unchanged receiver mutation counter proves ordinary-app isolation. If DUMP is unavailable, receiver stays non-exported and vehicleTest uses an in-app debug UI—never weaken permission.
  • goAsync() + bounded executor + finish(); compile-time actions/values; no raw IDs.
  • vehicleTest uses the release signing cert, avoiding debug↔release certificate mismatch after the one-time transition from the currently installed debug-key APK.

4.6 Production architecture

AmapEmissionArbiter is the sole sender: source frames, the 400ms heartbeat, gate-ready forced replay, Stop and source changes are commands on one monotonic session/sequence lane. Gate-ready cancels/coalesces a pending heartbeat and emits exactly one additional forced-replay token, not “one total broadcast.” The direct NavigationHudOwner → writeNavFrame path is retired for maneuver/distance; an M2 road writer exists only after exact consumer/order/clear proof.

4.7 Serialized mirror state machine

HUD requestrequest generation
READ_STATEphysical + mirror gates
APPLY_GATEsource-backed writes only
Coordinator lockfresh current frame?
FORCE_AMAP_REPLAYsame canonical payload
OBSERVEcluster + windshield truths
STOP/RESTOREstate reset + prior gates
  • All setting/gate HAL operations run off-main in one serialized mirror controller. All Amap sends—including heartbeat—run through AmapEmissionArbiter.
  • Toggle OFF invalidates pending gate callbacks. Independent profile applies its gate; coupled profile blocks/converts a lane-OFF request and explains that HUD follows cluster.
  • Enable completion submits FORCE_REPLAY(requestGeneration, sessionId, latestSequence). Arbiter drops stale tokens, coalesces pending heartbeat and orders concurrent source/Stop commands.
  • Stop uses the field-proven Amap reset sequence and restores only app-owned mirror gates. A production-confirmed physical HUD ON is durable and never auto-restored to OFF; temporary physical restoration is exclusive to consented D5 diagnostics.

4.8 Typed truths and capability model

enum class HudMirrorCapability {
    UNKNOWN,
    COUPLED_TO_CLUSTER,
    INDEPENDENT_GATE,
    UNSUPPORTED,
}

enum class RoadNameCapability {
    UNKNOWN,
    AMAP_PAYLOAD,
    SIDE_CHANNEL,
    UNSUPPORTED,
}

data class HudMirrorSnapshot(
    val physicalHudOn: Boolean?,
    val capability: HudMirrorCapability,
    val roadName: RoadNameCapability,
    val canonicalFrameSequence: Long?,
    val broadcastSent: Boolean,
    val clusterObserved: Boolean?,
    val hudObserved: Boolean?, // evidence only; not inferred from send/rc
)
Truth separation: Amap broadcast emitted ≠ AmapService consumed ≠ cluster visible ≠ HUD visible. Runtime may report emitted/gate state; exact-build evidence records physical observations. Other-vehicle owner evidence ranks hypotheses but does not set Seal capability.
UNKNOWN vs UNSUPPORTED: use UNKNOWN whenever artifacts are missing, a source-backed branch is untested, or the bounded matrix is incomplete. Use UNSUPPORTED only after every documented candidate is exhausted on the exact model/ROM/HUD/AmapService profile. User copy says “not supported by this ClusterNav build/profile,” never “hardware can never support it.”
Partial gate mutation: stop on first rejected setting operation; restore every earlier changed gate from recorded prior values in the same serialized generation; record primary + rollback outcome. Canonical Amap frame itself is one broadcast, not a fake multi-register transaction.

4.10 User flow

Independent-gate variant

  1. User requests HUD.
  2. Read physical + mirror gate.
  3. Apply proven gate if needed.
  4. Force replay latest Amap frame.
  5. Cluster remains active; HUD mirrors.
  6. HUD OFF toggles mirror gate only.

Coupled variant

  1. App detects/knows capability from field-proven profile.
  2. UI says “HUD follows cluster”.
  3. Canonical frame drives both surfaces.
  4. No fake independent checkbox action.
  5. Road line says supported/unsupported separately.
No proven Seal gate: while the bounded matrix is incomplete, keep cluster navigation working and show “Chưa xác định được mirror gate trên build/profile này; cluster vẫn hoạt động.” Only an exhausted exact-profile matrix may use “not supported by this ClusterNav build/profile.” In both states, perform no duplicate maneuver/distance writes.
