D3 — Helper mới returnAppToMain(adb, sh, app, vd, log): Boolean

Trung tâm hoá "bê 1 app khỏi VD về display 0 fullscreen" bằng đường KHÔNG-transition. Thay MỌI am display move-stack …0 trong đường SWITCH.

// ★ keepSession TÍNH BÊN TRONG — caller KHÔNG truyền (chống wire nhầm chỉ isKeepSession → force-stop CP/AA).
fun returnAppToMain(sh, app, vd): Boolean {   // true = app RỜI VD + FULLSCREEN d0 (R3 đủ 3 điều kiện)
  comp = resolveComp(app) ?: return false
  val keepSession = isKeepSession(app) || isPhoneProjection(comp, app)   // R5 — CẢ HAI vế (keepSessionApps rỗng mặc định)
  if (keepSession) {                       // CP/AA/sink — KHÔNG được giết phiên
    sh("am start --display 0 --windowingMode 1 -f 0x20000000 -n comp"); sleep(500)
    val off = app KHÔNG còn trên vd
    if (!off) log("⚠ $app (giữ-phiên) chưa rời VD — chấp nhận nằm sau B, KHÔNG force-stop, KHÔNG treo (OQ3)")
    return off        // giữ-phiên: chỉ cần rời VD; fullscreen-d0 không ép được vì không được đụng mạnh
  }
  // app thường: đường TẤT ĐỊNH, không-transition
  sh("am force-stop app"); sleep(400)                         // process death → CLOSE transition (an toàn A+B)
  sh("am start --display 0 --windowingMode 1 -n comp"); sleep(500)   // dựng lại fullscreen ở màn chính
  // ★ VERIFY R3/H4 — KHÔNG chỉ "rời VD" mà phải FULLSCREEN trên d0 (freeform-bé sót lại = nghi phạm freeze khi bấm Home).
  var e = pick(app, preferDisplay = 0)
  if (e == null || e.displayId != 0) return false             // relaunch hụt → báo caller (chưa đạt R3)
  if (e.mode != "fullscreen") {                               // còn freeform-bé → ÉP fullscreen lần nữa
    sh("am start -f 0x20000000 --windowingMode 1 -n comp"); sleep(400)
    e = pick(app, preferDisplay = 0)
  }
  return e != null && e.displayId == 0 && e.mode == "fullscreen"   // R3 = off VD + d0 + fullscreen
}
Vì sao force-stop là đường AN TOÀN NHẤT (dù mất state): research AOSP high-confidence + bằng chứng thực tế trên chính head unit này (đã force-stop Maps để clear GL surface, không treo). Đánh đổi mất-state được chấp nhận vì R1 (không treo) > giữ-state, và yêu cầu chủ dự án chỉ là "chạy bình thường" = app chạy lại bình thường. am start --display 0 đơn thuần bị research đánh giá RISKY (có thể no-op thành "brought-to-front" NGAY TRÊN VD = đúng bug app-cũ-nhảy-lên-top) → chỉ dùng cho keep-session, KHÔNG dùng làm đường chính.
⚠ Blast-radius restoreFullscreenOnMain (đọc kỹ trước khi code): hàm CastShell.restoreFullscreenOnMain hiện có am display move-stack $it 0 BÊN TRONG (bê stack app khỏi cluster-display) — đó CHÍNH là primitive NPE B. Trong đường SWITCH, returnAppToMain phải THAY THẾ mọi lời gọi restoreFullscreenOnMain (không gọi song song), để không bao giờ move-stack một task đang-hiện khỏi VD. Riêng nhánh HỦY của R6 (B bounce, chưa bám VD): tuyệt đối KHÔNG gọi restoreFullscreenOnMain(target) nếu target có thể còn 1 stack hiện trên VD — nó sẽ move-stack target khỏi VD (NPE B, một-lần/caught nhưng vi phạm R1). Nhánh này chỉ cần GIỮ old + thoát; target bounce về d0 tự nằm đó (fix fullscreen ở lần chiếu sau).

D4 — HUD tên đường (Track phụ)

ClusterBroadcaster.pushHud() hiện truyền lastCleanRoad (tên ĐẦY ĐỦ) vào BydHal.writeNavFrame(icon, seg, road) → road.toByteArray(Charsets.UTF_16LE) ghi vào INSTRUMENT_TARGET_NEXT_PATHNAME_INFO_SET (buffer BYTE cố định, nhỏ) → tràn buffer → firmware bỏ tên → chỉ còn mũi tên. Đơn vị "maxUnits" (trả lời nghi vấn byte vs char): buffer là BYTE; maxUnits đếm UTF-16 code-unit. Với text BMP (tiếng Việt NFC precomposed = 1 code-unit/ký tự) → số byte = 2 × maxUnits, nên maxUnits LÀ đơn vị đúng MIỄN LÀ chuỗi ở dạng NFC. Bắt buộc Normalizer.normalize(road, NFC) trước khi đo/cắt: (a) nếu input NFD (dấu tách rời) thì 1 ký tự = 2 code-unit = 4 byte → phá quan hệ 2×; (b) take(maxUnits) trên NFD có thể cắt GIỮA base + dấu kết hợp → rác hiển thị. Cũng vì buffer có thể cần ký tự kết thúc (NUL) → chọn 7 (14 byte) an toàn hơn 8 (16 byte, chạm mép ô ~16 byte).

Dedup theo bản viết tắt = ĐÚNG (dedup theo cái HIỂN THỊ): 2 tên khác nhau mà viết tắt trùng thì trên HUD vốn trông y hệt → nén là hợp lý; seg/icon đổi thì vẫn ghi. Không hardcode tên đường. "Võ Nguyên Giáp"→ ở 7: "VNG"; ở 8: "V.N.Giáp" — nâng hằng nếu trace HUD cho phép.
