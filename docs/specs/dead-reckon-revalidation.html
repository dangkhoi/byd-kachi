Context

Current behavior

  • Service listens to GPS/GNSS and BYD speed/steering, then replaces GPS_PROVIDER with a test provider during loss.
  • DEAD_RECKON integrates speed/heading; COLD_SEED freezes a saved position.
  • Periodic remove/re-add “peek” is required because replacing GPS stops useful real-GNSS observation on the tested Android 10 head unit.
  • Feature defaults to auto-on and restarts from app open, boot and package replacement.

Evidence available

  • Source-level mechanism and historical bug records.
  • Targeted Gradle run: 6/6 Wave1SafetyTest pass; only three assertions mirror one stationary gate.
  • Prior full suite: 218/218 pass, with no direct DR coverage.
  • Car checklist C1–C4 remains unchecked; no repository dr_log proves exact-build tunnel behavior or GMaps consumption.
Known field signal: historical notes record a 53-minute / 10-km drift episode and cyclic provider disruption. The user's current report is “lúc được lúc không, hên xui.” These are failure evidence, not validation evidence.

KEEP protocol if revival is proposed

  1. Pin APK SHA-256, source commit + dirty diff hash, vehicle/ROM, app-op and configuration.
  2. Run a control route with DR disabled; record real GPS, speed, steering and navigation continuity.
  3. Run at least five trials on each representative straight and curved tunnel.
  4. Record transition timestamps, input freshness, attempted/delivered mock fixes, visible map outcome, exit error and real-GPS recovery latency.
  5. Inject speed-HAL loss, provider setup failure, push failure, service stop and process kill.
  6. After every trial, independently prove test provider/marker absent and normal GPS usable; use physical power-button reboot where required.
Current result: required on-car evidence is NOT STARTED and the car is unavailable. Historical instability plus source-level unbounded/hidden failure modes means absence of evidence cannot be treated as a temporary KEEP.

Removal exit criteria

  • No auto-start or user-facing GPS aid remains
  • Upgrade cleanup is synchronous, idempotent and independently observed
  • Normal GPS works after stop, process death and physical reboot
  • Navigation + HUD and Cast tests remain unchanged
  • Public docs contain no unsupported tunnel-GPS claim
  • Public-repo security scan passes before any commit/push
