04

Design

D1 — Autostart split race fix (R1)

Root cause

HAI chủ autostart cùng nghe Idle và cùng dispatch: FloatingBubbleService.dispatchBootAutoStart() (đọc simple_cast_prefs) và CastAutostart.dispatchAutoStartIfEnabled() (Activity). Khi cả service lẫn Activity sống lúc mở app, cả hai phát CastSlot(LEFT)+CastSlot(RIGHT). Lượt thứ hai gặp slot đã chiếm → SLOT_OCCUPIED → setError → auto-recover về Idle, xoá mất CastingSplit. Nút nổi tô empty (trắng-xanh nhạt), không occupied (xanh đặc).

Fix

Một chủ autostart duy nhất = FloatingBubbleService (chạy cả khi Activity đóng — đúng mục tiêu ban đầu). Bỏ dispatchAutoStartIfEnabled() khỏi Activity (giữ nguyên checkbox/spinner setup UI). Trong service: cast LEFT, chờ state chuyển CastingSplit có left (verified) rồi mới cast RIGHT — thay cho postDelayed(2000) mù. Thêm cờ @Volatile autoStartDispatched chống re-entrancy nếu onStartCommand gọi lại.

D2 — Nút nổi: 3 ô ngang, bán trong suốt (R2)

BubbleRenderer.buildBubbleLayout đổi từ VERTICAL (Full trên, hàng L/R dưới) sang một LinearLayout HORIZONTAL chứa 3 ô cùng size theo thứ tự Trái · Phải · Full. Nhãn ô FULL đổi "Cả cụm" → "Full". Fill dùng ARGB bán trong suốt: idle ~0x33, occupied ~0x99 (xanh nhạt thấy content dưới). Alpha cửa sổ (IDLE_ALPHA/ACTIVE_ALPHA) giữ nguyên vai trò fade.

fill đục (cũ)fill bán trong suốt (mới)
Test đồng bộ: BubbleAccessibilityTest đang khẳng định zoneShortLabel(FULL)=="Cả cụm", ZONE_MIN_DP==56, và BRAND/BRAND_LIGHT alpha=0xFF. Cả 3 sẽ đổi theo thiết kế mới → cập nhật test cùng lúc (nhãn "Full", size thực tế, alpha bán trong suốt). CastUILifecycleSafetyTest cũng khẳng định ZONE_MIN_DP==56 → cập nhật. Giữ tiêu chí ≥48dp automotive.

D3 — 7 profile hình học / app (R4, R6)

Khoá profile = full hoặc {L|R}{leftPercent}. Với split, leftPercent∈{50,30,70} và side∈{LEFT,RIGHT} → 6 khoá; cộng full = 7. Mỗi profile là một DisplayConfig (đã có bounds+density). Persist trong simple_cast_prefs theo key config_<field>_<pkg>__<profile>.

// core/…/simplified/SimpleCastModels.kt — thêm (thuần Kotlin)
enum class CastProfile { FULL, L50, R50, L30, R30, L70, R70;
  companion object {
    fun of(side: ClusterSlotSide, leftPercent: Int): CastProfile = when (side) {
      ClusterSlotSide.LEFT  -> when (leftPercent) { 30->L30; 70->L70; else->L50 }
      ClusterSlotSide.RIGHT -> when (leftPercent) { 30->R30; 70->R70; else->R50 }
    }
  }
}

// SimpleCastPrefs — thêm API theo profile (mặc định giữ tương thích khoá cũ = FULL)
fun displayConfigFor(pkg: String, profile: CastProfile): DisplayConfig?
fun saveDisplayConfig(pkg: String, profile: CastProfile, config: DisplayConfig)

Khoá cũ config_*_<pkg> (không hậu tố) tiếp tục là profile FULL để không mất config đã lưu; profile mới thêm hậu tố __L30 v.v. FakePrefs + SharedPrefs impl cập nhật đồng bộ (R8).

D4 — Resize theo slot khi split (R5)

Thêm SimpleCastCoordinator.resizeActiveSlot(side, l,t,r,b): chỉ chạy ở CastingSplit, tìm taskId của app đúng slot (qua findTaskIdForPkg), am task resize, và persist vào profile (pkg, ratio, side) CHỈ khi shell OK. CastGeometryEditor.updateVisibility(CastingSplit) dựng resize view cho từng slot có app (mỗi view giới hạn kéo trong dải ngang của slot) + nút DPI. handleCastSlot: nếu profile đã lưu có bounds → dùng bounds đó (thay vì mặc định theo ratio trong AppMover.fitToCluster); nếu chưa → mặc định ratio.

Giới hạn OS (DPI split): wm density là display-global trên Android 10 — hai app trên cùng display 1 KHÔNG thể có 2 DPI khác nhau đồng thời. Quyết định: lưu DPI theo profile (dùng đủ khi app đó chiếm full / là app được chỉnh gần nhất); ở split, chỉnh DPI slot nào thì áp cho cả display và lưu vào profile slot đó — "chỉnh sau đè trước". Ghi rõ hạn chế này ở UI + KDoc. Bounds (vị trí+size) thì per-app thật sự (per-task) nên không vướng.

D5 — CP/AA resize (trả lời câu hỏi 5) — optional T5

Freeform KHÔNG dùng được cho CP/AA

Đây là lý do CastSlotValidator chặn CP/AA khỏi slot và verifyFullscreenStackAvailable từ chối freeform: CP/AA ở freeform trên DiLink3 gây surfaceflinger crash, cụm kẹt phải power-cycle. Nên "resize đỉnh cao" (per-app am task resize rect) — vốn cần freeform — không mở cho CP/AA.

Nhưng CÓ cửa khác (an toàn)

CP/AA vốn đã "resize" bằng đường display-global: wm size + wm overscan + wm density (CP=1422×800 overscan 10,-120,10,50; AA=1920×1080). CP/AA tôn trọng các lệnh này (khác freeform bounds). Cửa khả thi: một editor chỉnh wmSize/overscan/density cho CP/AA, persist theo app-type. Hạn chế: chỉ chỉnh cả display (letterbox căn giữa), không cắt nửa, không offset — nhưng đủ để phóng to/thu nhỏ/đẩy lề nội dung CP/AA an toàn.

Đề xuất: đưa T5 vào scope nếu owner muốn — làm một "CP/AA size" editor (3 thanh: width, overscan, DPI) chỉ hiện khi CastingFull app protected. Nếu không, giữ nguyên config đo sẵn. Cần owner chọn.

D6 — Boot-autostart projection ownership (R10)

Gap

Autostart chỉ bắn khi coordinator tới Idle, mà Idle cần openProjection(). Trước fix, openProjection() CHỈ được gọi ở MainActivityCastController (Activity). Boot xe không mở Activity → state đứng ở Off → listener autostart trong FloatingBubbleService chờ mãi → không cast. Bubble hiện nhưng cụm không chiếu.

Fix

  • openProjection() thành idempotent (chỉ mở từ Off/Error; đang mở/idle/casting → no-op) — cả service lẫn Activity gọi đều an toàn.
  • FloatingBubbleService.dispatchBootAutoStart: khi autostart bật, tự openProjection() với retry có giới hạn (5×, cách 3s) cho adb-loopback chưa sẵn lúc boot.
  • Sở hữu vòng đời: autostart bật ⇒ Activity onDestroy KHÔNG đóng projection (service giữ để cast sống khi đóng Home). Autostart tắt ⇒ hành vi cũ (Activity đóng).
Bảo toàn hành vi: autostart TẮT → không mở projection lúc boot (giữ đồng hồ/gauges), Activity vẫn mở/đóng như cũ — non-autostart users không đổi gì. Chỉ khi autostart BẬT mới đổi (đúng ý người bật autostart: muốn cụm tự chiếu khi lên xe).
