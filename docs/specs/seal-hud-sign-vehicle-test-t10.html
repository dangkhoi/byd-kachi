2.2 User story and success boundary

User story: Là owner của một thử nghiệm hobby trên xe đang đỗ, tôi muốn thu bằng chứng HUD/navigation/speed-sign theo từng bước có stop gate và rollback rõ ràng, để chỉ những candidate đã được chứng minh và review offline mới có cơ hội được thử ghi trong một phiên sau.

In scope

  • Lập và sau approval mới triển khai transport T10 trong vehicleTest.
  • Exact identity, sender/permission/profile preflight.
  • Session N chỉ đọc: sáu discovery probes, H8 và bốn milestone observations.
  • Offline review, registry/pack N+1 regeneration và independent approval.
  • Conditional one-dimension mutation, clear, inverse, restore và D-H0/M1–M4 sealing.

Out of scope

  • Không chạy xe ngoài đường công cộng hoặc thử khi xe đang di chuyển.
  • Không dùng raw ID, MASS, free-form selector, guessed enum hay payload không source-backed.
  • Không đổi AmapService khỏi vai trò canonical navigation route.
  • Không hợp nhất speed-sign vào navigation transport.
  • Không implement T11/release wiring, commit, push hay release trong plan phase.

Design

4.1 End-to-end control flow

closed identity/control boundaryread/observemutation path—absent in Session N
Key boundary: planner data never becomes shell text. Runtime resolves typed probe/operation IDs through fixed catalogs. The T10 adapter is the only bridge from the neutral pack contract to live CarExec/vehicleTest transport.

4.2 Roles and two-person rule

4.3 Physical setup and go/no-go

Mandatory before any connection

  • Private, level, ventilated location; no public-road movement.
  • Vehicle stationary, selector P, parking brake engaged.
  • Compatible battery support attached and stable.
  • Approved stop threshold visible to both people.
  • Operator and observer both present; communication phrase “STOP T10” agreed.
  • HUD/cluster visible without blocking driver controls.
  • Emergency access and physical power control unobstructed.

Immediate no-go

  • Vehicle/profile does not match approved identity.
  • Any pre-existing unexpected DTC/warning is unresolved.
  • Battery support/threshold unavailable or unstable.
  • Only one person is present for a mutation-capable window.
  • Vehicle cannot remain stationary/P/parking-brake state.
  • Raw evidence storage is not local/ignored or privacy plan is missing.
Movement rule: if the vehicle leaves stationary/P state at any time, start no new row. A read-only row stops. A started mutation row performs only its pre-armed clear/restore/recovery path, then the session ends.

4.4 Exact identity preflight—before SESSION_START

  1. Load one handoff. Use only docs/_handoff/hud-sign-vehicle-test-candidate.json; no override path, renamed APK or historical artifact.
  2. Re-hash local bytes. Compare APK, source snapshot, candidate diff, registry, pack and candidate-set identities with the handoff/template.
  3. Verify signer from APK DER certificates. At least one signer; sorted certificate hash set must match signerSha256.
  4. Verify build role. Variant must be VEHICLE_TEST; release/main must contain no probe surface.
  5. Verify sender/component/permission/profile. Every typed ID must match the frozen exact identity. Unknown permission defaults deny; do not weaken export rules.
  6. Select one transport explicitly. Resolve the authorized serial/transport; reject zero, multiple, offline or unauthorized devices.
  7. Compare target profile using read-only facts. Model/ROM/profile match is recorded as typed/sanitized evidence, never raw private identifiers in tracked files.
  8. Instantiate Freeze only on full equality. Any mismatch stops before SESSION_START and emits no vehicle ledger event.

4.6 Session N closeout—still on site, still no promotion

  1. Finish every started read-only/milestone automaton. Record one terminal outcome per row; never reconstruct from memory later.
  2. Close transport cleanly. Do not install another build or open an ad-hoc shell after the frozen final row.
  3. Record physical baseline. Cluster/HUD/warnings and vehicle stationary state must match the preflight baseline.
  4. Seal local raw evidence. Hash files locally, retain them in ignored storage, and create only metadata references for review.
  5. Export the ledger. Validate hash chain/schema before leaving; an invalid ledger means the session is inconclusive.
  6. End authorization. The on-site window closes. Discoveries cannot be acted on until a new pack and a new explicit authorization exist.

Promotion checklist

  • Fixed selector and source citation.
  • Exact config + READ_WRITE/WRITE access.
  • Java type, provider and permission.
  • Concrete app-UID transport proof.
  • Bounded source-backed value domain.
  • Prior read + immediate read-back operation.
  • Required clear + ordered inverse.
  • Expected consumer/surface and ownership.
  • Risk accepted; no absolute reject.

Outcomes

  • READY_FOR_FIELD: appears as one mutation row in N+1.
  • MUTATION_REVIEW: evidence improved but no row.
  • READ_ONLY_READY: read-only row only.
  • REJECTED: never appears; append tombstone if newly invalidated.
  • No candidate ready: N+1 remains read-only/blocked; do not schedule mutation.
Non-negotiable: S11 remains MUTATION_REVIEW until all missing domain/prior/read-back/clear/inverse proof closes. S12 remains REJECTED regardless of observed behavior because its shape contains a raw selector.

4.9 Common one-dimension mutation transaction

Preconditionidentity · safety · dependency
Read priortyped value + physical baseline
Arm inverseimmutable frame pushed first
Mutate onceone fixed operation ID
Read backtyped equality/status
Observeindependent surfaces
Clearcontent plane
Restoreprior + verify · then terminal
  1. Re-run identity and physical preconditions. Reject any drift, warning, transport ambiguity or unresolved dependency.
  2. Read exact prior state. Capture typed value/status and required physical surface baseline. A missing/ambiguous prior blocks the row.
  3. Build an immutable rollback frame. Copy prior plus ordered inverse IDs and expected post-restore checks.
  4. Push/arm the frame before the write call. It remains live even if the call throws, times out or partially applies.
  5. Execute exactly one mutation operation. No second field/gate/value change is allowed inside the row.
  6. Read back immediately. Compare exact typed state; a mismatch marks mutation failure but does not skip cleanup.
  7. Observe every required surface independently. Record cluster/HUD/warnings separately; never infer a sibling surface.
  8. Clear the content plane. Use only the candidate’s approved clear operation/sentinel. D-H0 is the explicit no-content-plane exception.
  9. Restore the prior state. Execute ordered inverse from the armed snapshot, not from mutable caller data.
  10. Verify restore. Typed read-back and physical baseline must both pass. Only then pop the frame.
  11. Emit terminal result. PASS requires mutation/read-back/observations/clear/restore shape. FAIL/INCONCLUSIVE still require restore PASS.
  12. Return to a clean baseline before the next row. Normal execution never overlaps two armed frames.

4.11 Stop gates and recovery

Stop before mutation / start no new row

  • Any exact-identity or signer mismatch.
  • Unknown selector, type, provider, permission, value domain or consumer.
  • Vehicle/profile mismatch or transport not uniquely selected.
  • Vehicle leaves stationary/P/parking-brake state.
  • Battery monitor crosses the approved threshold or support becomes unstable.
  • Unexpected DTC, warning, odor, heat, display instability or observer STOP call.
  • Prior value unavailable/ambiguous; baseline cannot be observed.
  • Read-only discovery suggests a new operation not in Freeze.

After a mutation attempt

  • Read-back mismatch, exception, timeout or transport interruption: start no new mutation; finish approved clear/restore.
  • Unexpected surface or warning: capture minimal evidence, then clear/restore.
  • Deadline expires: current row still finishes clear/restore; later rows become skipped.
  • Clear fails: continue to restore; terminal cannot be PASS.
  • Restore fails: retain frame, emit recovery block, end all normal execution.
  • No automatic reboot. Any approved reboot evidence uses physical head-unit power control; adb reboot is not equivalent.

4.13 Evidence fields and privacy boundary

Tracked metadata allowed

  • Typed artifact aliases and SHA-256 identities.
  • Session/row/event/result IDs and monotonic offsets.
  • Candidate/operation/probe IDs from closed schemas.
  • PASS/FAIL/INCONCLUSIVE/BLOCKED outcomes and fixed reason IDs.
  • Sanitized surface booleans/categories.
  • Clear/restore evidence references and hashes.
  • Reviewer identity alias and finding counts.

Raw/local only—never tracked

  • VIN, device serial, private IP, GPS, route/destination.
  • Credentials, ADB keys, tokens or signing private material.
  • Installed-app inventory and package dumps beyond sanitized aliases.
  • Full logcat/dumpsys/provider rows/property payloads.
