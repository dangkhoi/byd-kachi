4Design

I1 — HUD arrow mirror: send the CAN code, not the AMAP code off-car fix

The neutral Maneuver has two encoders by design: toAmapIcon() (cluster lane, via the AUTONAVI broadcast; left=2, right=3) and toHudIcon() (windshield HUD, INSTRUMENT_GUIDE_INFO_SIMPLE_SET, CAN table; left=1, right=2). toHudIcon() was unit-tested but never called in production — the delivery fed the AMAP code (maneuverCode) into the CAN feature. AMAP left=2 read by the HUD as CAN 2=right → exact L↔R mirror. The cluster stays correct because it is driven by the separate broadcast.

I2 — Smooth marquee off-car fix

Root: Prefs.marquee defaulted OFF; when ON, roadWindow(name, scrollTick, 7) advanced by scrollTick, which handleEmission bumps on source-frame + heartbeat + forced-replay → uneven = jerky. Change: default ON + UI toggle (cb_marquee, both layouts); offset is now time-based — tick = (elapsedRealtime − roadShownAtMs) / MARQUEE_STEP_MS (700 ms), roadShownAtMs reset on road change / session-reset / stop → even, slow, restarts from the start of each new name. Firmware re-renders per 400 ms send, so this is the smoothest a fixed char cell allows.

I3 — 10m smallest step off-car fix

NavParse.quantizeDisplay <100m branch (m/5)*5 → (m/10)*10. Test updated (quantizeDisplay(47) 45→40).

I4 — Cluster-mode selector off-car: OFF + apply-now on-car: value map

Mode is written per nav-frame (SET_NAVI_SCREEN_STATUS_SET = Prefs.navClusterScreenMode). "Simple only after reboot" ⇒ the OEM applies nav-screen mode at session start, not mid-session; when parked, icon/seg/road are static so the owner's dedup also suppresses re-writes. Off-car changes:

  • OFF → NavigationHudOwner delivery routes mode==NAV_SCREEN_OFF to clearNavFrame (status=4), not screen=0 (which did nothing).
  • Apply now → owner.reapply() busts dedup and submits clearFrame(status=4) then re-pushes (status=2 + new mode) = a 4→2 re-assert; the cluster-mode spinner calls NavRepository.reapplyClusterMode on change.
On-car (open)
Which value (0..3) maps to Đơn giản/Nhỏ/Toàn/OFF, and whether the 4→2 re-assert makes it render without a reboot (if the OEM only applies at session start, this is best-effort). Sweep via navopen (§7).

I5 — Autostart on boot off-car fix

RebindReceiver handled BOOT_COMPLETED by rebinding the listener + starting the bubble (self-stops if Cast off) but did not launch the app. Change: relaunchAfterUpdate → shared launchHome; called on BOOT_COMPLETED (auto-open the app; background-activity-start allowed via the SYSTEM_ALERT_WINDOW exemption). Bubble now gated on SimpleCastRuntime…castEnabled() (start only when Cast on). MY_PACKAGE_REPLACED still calls launchHome, so the update path relaunches. The 1.13 default-OFF master switch does not remove autostart.
