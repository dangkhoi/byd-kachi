2. Context

Phiên on-car 2026-08-17 xác nhận: overlay badge tốc độ vẽ được lên cụm khi Cast Cluster BẬT (badge sống trên surface cast ảo display 1); dữ liệu tốc độ (60) lấy từ VietMap. Nhưng: (a) UI chỉnh badge hiện tại (4 nút góc + size ±) khó xài; (b) mục "Nguồn tốc độ + cảnh báo" đang nằm nhầm ở cột Navigation + HUD (trái) trong khi badge là thứ của Cluster Cast (phải); (c) VietMap còn bắn cảnh báo/camera (widget "Cảnh báo") và có thể nhiều field khác mà app chưa khai thác.

Ba việc trong spec này (owner yêu cầu):

  1. Dời mục lấy dữ liệu VietMap từ cột trái (Nav+HUD) sang cột phải (Cluster Cast) "cho đúng" + cho bind nguồn.
  2. UI đặt badge trực quan: hình chữ nhật đại diện cụm (như editor resize khi cast app) + kéo cục badge tới vị trí bất kỳ + chỉnh size, WYSIWYG, lưu lại → vẽ đúng vị trí đó lên cụm.
  3. Log TOÀN BỘ tín hiệu VietMap (tốc độ + camera/cảnh báo + field lạ + ảnh icon) để mai chạy lấy hết, off-car đánh giá cần vẽ thêm gì lên cụm.

3. Requirements

Part A — Dời nguồn VietMap sang cột Cluster Cast

  • A1. Mục "Nguồn tốc độ + cảnh báo (biển báo · camera)" (label + spinner_speed_source + nút "Dữ liệu VietMap" btn_vietmap_widget_diag) chuyển từ card Navigation + HUD sang card Cluster Cast, ở CẢ 2 layout (layout/ dọc + layout-w960dp/ ngang 2 cột).
  • A2. Có nút/luồng bind nguồn VietMap (widget speed + alerts) rõ ràng trong mục mới, kèm dòng trạng thái bind (bound / chưa bound / provider missing).
  • A3. Không vỡ pipeline nav; các findViewById id cũ vẫn còn (đổi vị trí, không đổi id).

Part B — UI đặt vị trí + kích thước badge trực quan

  • B1. Hiện hình chữ nhật tỉ lệ cụm (display 1, mặc định 1920×720, đọc từ display config như CastResizeView) trong card Cluster Cast.
  • B2. Bên trong có cục badge (vẽ bằng SpeedBadgeView thật → WYSIWYG, hiện số mẫu vd 50). User kéo cục badge tới vị trí bất kỳ; thả ra thì lưu vị trí (toạ độ cụm).
  • B3. Bên dưới có chỉnh size (thanh trượt/± ), size phản ánh ngay vào cục badge trong hình chữ nhật.
  • B4. Chọn xong size + vị trí → lưu → overlay thật vẽ đúng vị trí + size đó lên cụm (khi cast active). Bỏ mô hình "4 góc" cũ, chuyển sang toạ độ tuyệt đối.
  • B5. Có nút "Xem thử trên cụm" (force-show badge) để đối chiếu preview ↔ cụm thật; và nút Đặt lại.

Part C — Log toàn bộ tín hiệu VietMap (cho chuyến mai)

  • C1. Log định kỳ (verbose-gated) mọi raw value app đã đọc: currentSpeed, speedLimit, và cả 2 alert (limit / distance / imageVisible / imageHash) + freshness + providerVersion.
  • C2. Khám phá field lạ: duyệt toàn bộ cây view của widget "Cảnh báo" (và "Tốc độ") dump MỌI TextView (id-name + text) + MỌI ImageView (id-name + visible), kể cả field app chưa parse → để off-car biết VietMap còn bắn gì.
  • C3. Lưu ảnh icon cảnh báo (warning_alert_image / second_…) ra PNG khi đổi (theo imageHash) → off-car xem icon camera/police/… trông ra sao để quyết vẽ gì.
  • C4. Toàn bộ CSV + PNG ghi vào thư mục files (như telemetry hiện có), verbose-gated (debug auto-verbose đã bật), degrade-safe, không chặn thread widget.

4. Design

4.1 Tổng thể — tái dùng pattern có sẵn

4.2 Part A — layout

  • Cắt block "Nguồn tốc độ + cảnh báo" khỏi card Nav+HUD, dán vào card Cluster Cast (trong cast_body, trên cast_geometry_container), ở cả layout/activity_main.xml và layout-w960dp/activity_main.xml. Giữ nguyên id.
  • Bind nguồn: dùng lại VietMapWidgetBridge/VietMapWidgetDiagActivity (đã có bind). Thêm dòng trạng thái bind + nút "Kết nối nguồn VietMap" nếu chưa bound. MainActivity wiring giữ nguyên logic, chỉ đổi nơi các view được đặt.

4.3 Part B — BadgePlacementView + Prefs toạ độ tuyệt đối

  • Prefs (thay mô hình 4 góc): badgeX, badgeY = toạ độ TÂM (hoặc top-left) badge theo px CỤM (0..W, 0..H); badgeSizeDp giữ (clamp 60..240). Bỏ/deprecate badgeCorner/badgeDx/badgeDy (giữ đọc cũ để migrate 1 lần: corner→x,y tương ứng).
  • Pure core: BadgeLayout thêm hàm thuần clampPosition(x,y,size,W,H) (giữ badge trong cụm) + unit test. Không phụ thuộc Android.
  • BadgePlacementView (app, mẫu CastResizeView): vẽ hình chữ nhật tỉ lệ cụm (W×H từ display config), vẽ cục badge = SpeedBadgeView thu nhỏ theo scale; onTouch ACTION_MOVE kéo badge (clamp trong rect), ACTION_UP → callback (xCluster,yCluster) → lưu Prefs + overlay.refreshLayout(). Slider size → cập nhật marker + Prefs + refresh.
  • SpeedBadgeOverlay.buildLayoutParams(): gravity=TOP|LEFT, x=Prefs.badgeX, y=Prefs.badgeY (đổi hệ nếu lưu tâm), width=height=size*density. refreshLayout() giữ nguyên (đã có).
  • 1 overlay dùng chung (gộp BUG-1 — có thể làm cùng hoặc tách track B1 trong kế hoạch off-car; spec này giả định overlay đơn).

4.4 Part C — VietMapSignalLog

  • VietMapSignalLog (app): mỗi lần snapshot đổi (hook ở VietMapWidgetBridge nơi apply RemoteViews), verbose-gated, ghi 1 dòng CSV vietmap_signal_*.csv: ts, freshness, providerVersion, currentSpeed, speedLimit, a1Limit/a1Dist/a1ImgVisible/a1ImgHash, a2… .
  • Dump field lạ: thêm hàm trong VietMapWidgetExtraction duyệt cây (root đệ quy) liệt kê mọi TextView (resource-entry-name + text) + ImageView (name + visible) → ghi vietmap_views_*.csv (chỉ khi verbose). Dùng Resources.getResourceEntryName để lấy tên id thật của VietMap.
  • Ảnh icon: khi imageHash đổi, lưu bitmap alert image → diag/vietmap-alert-<hash>.png (đã có capturePixels; thêm nhánh ghi PNG). Off-car map hash→loại (camera/police/…).
  • Off-thread cho hash/ghi (đã có hashExecutor); ghi CSV nối tiếp, RFC-4180 (dùng CsvEscape có sẵn). Degrade-safe.
