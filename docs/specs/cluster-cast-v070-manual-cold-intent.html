Context

Exact failure in 0.69

  • Retry stopped before transaction creation; durable epoch stayed 0, transaction/stable session stayed null and ledger had zero rows.
  • dumpsys display textual headings were counted as logical displays.
  • am stack list places displayId on parent Stack; current preflight expects it on child taskId.
  • A generic 500 ms message overwrote the exact preflight result.

Why parser-only is insufficient

  • Current UI classifies missing cluster display as recovery and exports only Retry + Diagnostics.
  • Current bootstrap succeeds only to IDLE_VERIFIED; Activity returns without placing the selected app.
  • AndroidObservedStateParser repeats the same parent/child mistake and can falsely report an active display as empty.
  • isDisplayClean also checks displayId on task lines and can authorize reset from false-clean evidence.
Process failure, not test-count failure: the previous 46-suite/356-test baseline did not exercise the ROM producer shape. The next vehicle readiness decision is based on replaying sanitized real-shape fixtures through every consumer, not on aggregate test count alone.

Scope boundary

In 0.70

  • Manual cold intent end-to-end.
  • Strict display + AM parsing.
  • Cold app selection/action gating.
  • Exact operation status.
  • Warm path non-regression.
  • Off-car evidence and reviewed exact source.

Deferred candidate

  • Application icons.
  • Floating-button control surface.
  • Default app selection.
  • Boot autostart/auto-bootstrap.
  • New protected-package policy.

Forbidden here

  • Legacy Cast mutation imports.
  • Navigation/HUD changes.
  • Toolchain/dependency migration.
  • APK build/install or vehicle action.
  • Historical artifact overwrite.

Design

D1 — One user intent, two durable transactions

normal control pathverified terminalfailure/Stop fence

The BOOTSTRAP and CAST ledgers remain separate so each command set has an exact postcondition and compensation budget. The high-level runner owns only orchestration; it never emits shell commands and never creates a second journal. A re-entrant scope over the existing executor lease prevents another mutation from interleaving at the stable boundary, while requestStop() may still bump the durable epoch and fence the live gateway without waiting for that lease.

D2 — Explicit cold classification

Presentation eligibility

A pure CastColdStartClassifier combines the pristine durable envelope with the exact missing-named-display observation and rollout ownership. It may produce COLD_PRISTINE for rendering, but carries no permission to mutate.

  • stableSession == null
  • transaction == null
  • durableEpoch == 0
  • no Stop/pending rollback/adjustment
  • effective V2 with no current action owner

Mutation authorization

CastColdBootstrapPreflight remains the authority and reruns the complete raw check inside transaction creation. Any drift between the UI hint and locked truth blocks before the ledger/opcode.

  • exact vehicle tuple
  • numeric Display 0 only
  • WM + AM main-only
  • active user + three animations
  • nonblank appops

COLD_PRISTINE is added only to the UI coarse-state schema. It is not added to StableState; this prevents an absent display from being represented as a verified durable terminal.

D3 — Shared strict real-shape parsers

The new V2 parser is intentionally separate from legacy StackParse: the legacy parser ignores malformed lines and uses throwing integer conversion, while this safety boundary must preserve malformed candidates as a blocking result. Within V2, parsing is not duplicated: the same immutable snapshot feeds all three consumers.

D5 — Thin Activity and exact local status

State holder

Extract a pure/tokenized CastOperationStatus helper with begin, complete, snapshot and expiry. Only the active token may complete. Result TTL is exactly 4,000 ms.

Priority: durable Stop/recovery/manual → current local operation → steady projected state.

Activity

Activity gathers user input and renders immutable models. DADB, raw parsing, orchestration and blocking waits remain on the existing worker path. UI changes return through the main thread.

Rename/split the current generic timestamp into Stop-only acknowledgement and normal-operation overlay; extract helpers so Activity stays below 500 LOC.

Add cold-pristine UI contract

Add COLD_PRISTINE, pure classification and total action mapping. Regenerate canonical schema version/hash and replace the old Retry-only contract test.

T3 · Intent

Compose BOOTSTRAP → CAST under the existing lease

Introduce the high-level manual-intent runner. Validate target, persist latest target with five BOOTSTRAP rows, execute/verify bootstrap, consume latest target at the stable boundary, refresh target evidence and run the existing ordinary CAST transaction.

  • No placement before durable IDLE_VERIFIED
  • Exactly one mutation owner and one store/journal
  • Stop at every cut point suppresses continuation
  • Process death never replays ISSUED rows
  • Warm CAST/SWITCH bypasses bootstrap opcodes
T4 · UI

Extract status holder and thin Activity

Move local operation overlay and high-level result mapping out of the 499-line Activity. Keep normal work off main; render immutable model on main.

  • Durable recovery/Stop overrides local success
  • Stop 500 ms acknowledgement tests remain byte-for-behavior equivalent
  • Activity and all touched files ≤500 LOC

Focused, full and static off-car validation

Add table-driven/parser tests and an end-to-end recording-gateway suite for normal and protected manual cold intent. Run focused tests after each boundary, then the complete JVM suite once all slices converge.

Use separate report-only reviews for parser producer↔consumer, transaction composition and UI status. The primary agent applies any patch, reruns focused/full tests, then rechecks the changed boundary until zero actionable P0–P3 findings.
