D5 — #1 Cast kẹt "cửa sổ" (R6) · investigate

Giả thuyết: khi cast qua lại VietMap, task bị đặt windowing-mode freeform (multi-window) qua am task resize/wm, và đường "về màn chính"/return không reset về fullscreen (mode 1) → app kẹt dạng cửa sổ, cả trên cluster lẫn khi kéo về main. Đào CastShell (windowing-mode set/restore) + CastFacade/AppMover (return/stop path) + coordinator return intent. Fix hướng: return/stop phải phát lệnh đặt lại windowing-mode fullscreen + full bounds cho task trước khi trả về HOME display; đảm bảo state máy không kẹt CastingSplit/Freeform. Đọc trước, xác định root-cause, rồi vá + test state. Xác nhận cuối on-car.

Root cause + fix (Wave 4 · 2026-08-11):
  • Đường wired = SimpleCastCoordinator → AppMover (không phải CastShell/CastFacade — đó là pipeline v2 chưa wire). NORMAL app được cast bằng am start --display 1 --windowingMode 5 (FREEFORM) rồi am task resize → task ở freeform mode với bounds cụm.
  • Root cause: AppMover.returnToMain nhánh NORMAL chỉ phát am start --display 0 --windowingMode 1 -n '<comp>'. Trên A10/DiLink3 lệnh trần này KHÔNG reset đáng tin windowing-mode của một task ĐANG chạy: task về display 0 nhưng GIỮ freeform + rect cụm [0,0,W,H] ⇒ hiện thành cửa sổ nổi lệch layout; mỗi vòng cast/return giữ nguyên kẹt (owner: "qua lại → cửa sổ, 'về màn chính' vẫn cửa sổ"). Recipe đúng đã tồn tại ở legacy CastShell.restoreFullscreenOnMain (LAUNCHER + FLAG_ACTIVITY_SINGLE_TOP + verify/re-issue, field-validated 2026-07-22) nhưng CHƯA từng được port sang AppMover đơn giản hoá.
  • Fix: thêm AppMover.fullscreenReturnCommand(component) = am start --display 0 --windowingMode 1 -f 0x20000000 -a android.intent.action.MAIN -c android.intent.category.LAUNCHER -n '<comp>' (verb DUY NHẤT đổi windowing-mode task đang chạy trên A10; SINGLE_TOP + LAUNCHER để reparent task cũ vào fullscreen stack thay vì spawn activity trùng). returnToMain NORMAL phát recipe này rồi self-heal: nếu isWindowedOnMain(pkg) (đọc am stack list + wm size — stack trên display 0 có bounds nhỏ hơn full display) → re-issue một lần. CP/AA GIỮ NGUYÊN (am stack move-task). State machine: handleStop đã luôn về Idle (không kẹt freeform/split); test chốt lại điều đó.
  • App-side vs on-car: phần app-side reset (recipe + re-issue) đã implement. Xác thực windowing-mode SÂU (đọc dumpsys window displays như CastShell làm on-car) là phần chỉ khẳng định được trên xe — ghi ở §Open Questions.
