01

Context

op39 (service call AutoContainer 2 i32 1000 i32 39 s16 "", "简易导航 / Simple navigation") là cách bật overlay nav OEM ở giữa cụm (mũi tên + cự ly + tên đường + ETA sống), do ClusterNavLaneWidget phát trong nav-only mode (Cast master switch TẮT) khi đang dẫn đường. Nó là track NAV, tách khỏi track Cast.

Triệu chứng on-car (2026-08-12)

Cài 1.07, chọn [Giữa + ETA], mở dẫn đường → cụm chỉ hiện nav nhỏ/ở trên (kiểu OEM default do broadcast vẽ), KHÔNG lên op39 giữa. Sáng cùng ngày bắn op39 bằng adb laptop thì lên giữa OK.

Off-car trace — cái ĐÚNG

Lệnh op39 trong app trùng khớp lệnh proven trong scripts/vehicle/nav-mode-probe.sh (đúng service AutoContainer cho DiLink3.0, đúng cả s16 ""). Vì cụm vẫn hiện nav nhỏ (broadcast tới nơi) ⇒ onNavActive ĐÃ chạy. Nên op39 chết ở gate hoặc ở đường giao — KHÔNG phải sai lệnh.

Ba phát hiện dẫn tới scope:
  • Đường giao khác nhau: laptop bắn qua adb host (uid-2000 shell, luôn được). App bắn qua dadb loopback localhost:5555 — máy tự nối chính nó; cần adbd đang nghe TCP 5555 + key được authorize. Nếu 5555 rớt (vd sau power-cycle — bước dọn dẹp bắt buộc), loopback fail ⇒ op39 (và cả Cast/WazeHUD) fail âm thầm.
  • Bug retry (D1): onNavActive set active=true + lastAssertAtMs TRƯỚC khi shell chạy. Lần bắn đầu fail vẫn bị coi là "đã assert" ⇒ chặn retry suốt REASSERT_MS=30s, kể cả khi loopback sống lại giữa chừng. Khớp đúng triệu chứng "không bao giờ lên giữa".
  • Fail im lặng (D3): kết quả op39 bọc trong runCatching, chỉ log; khi bị gate Cast thì không log dòng nào. Người dùng không có tín hiệu nào để biết vì sao.
Bất khả thi (đã chốt, KHÔNG làm): app non-root không thể tự bật adb-over-tcp (service.adb.tcp.port cần shell/root — mà shell chính là thứ đang chết → gà-và-trứng). Nếu nguyên nhân là 5555 rớt thì app chỉ phát hiện + báo, việc bật lại 5555 phải làm ngoài (laptop adb tcpip 5555). Xác nhận cuối (case gate vs loopback) vẫn cần logcat trên xe — nhưng sau D1–D4 chỉ tốn 1 lần mở nav.

D1 · Sửa retry — chỉ tiêu debounce khi thành công

Tách quyết định timing thành hàm thuần để unit-test không cần Android:

const val REASSERT_MS = 30_000L          // giữ sau khi assert THÀNH CÔNG
const val RETRY_AFTER_FAIL_MS = 4_000L   // backoff giữa các lần thử khi CHƯA thành công

/** Thuần: có nên (re)issue op39 lúc now không? Success giữ 30s; sau một lần thử
 *  bất kỳ, không thử lại nhanh hơn mỗi 4s (tránh spam dadb ở nhịp notification). */
fun shouldIssueNow(nowMs, lastOkAtMs, lastAttemptAtMs): Boolean {
    if (lastOkAtMs != 0L && nowMs - lastOkAtMs < REASSERT_MS) return false      // hold sau success
    if (lastAttemptAtMs != 0L && nowMs - lastAttemptAtMs < RETRY_AFTER_FAIL_MS) return false
    return true
}

onNavActive chỉ cập nhật lastOkAtMs khi ShellResult.success; lastAttemptAtMs cập nhật mỗi lần chạy shell. Fail ⇒ lastOkAtMs không đổi ⇒ sau 4s notification kế tiếp thử lại; success ⇒ hold 30s rồi re-assert (giữ hành vi cũ). Chạy trên single-thread executor như hiện tại.

D2 · Log quyết định (một dòng khi đổi trạng thái)

Thêm enum runtime + setter dedupe log:

enum class Op39Status { IDLE, ASSERTED, GATED_CAST, GATED_SMALL, SHELL_UNREACHABLE }
@Volatile var status = Op39Status.IDLE; private set
@Volatile var detail = ""; private set   // "exit=0" | "exit=-1 " | lý do gate

// chỉ log khi status ĐỔI → không spam ở nhịp noti
gated cast   → Log.i(TAG, "op39 skip: Cast đang bật (nav nhường cụm)")
gated small  → Log.i(TAG, "op39 skip: chế độ Nhỏ/ở trên (không assert op39)")
asserted     → Log.i(TAG, "op39 asserted ok (exit=0)")
unreachable  → Log.w(TAG, "op39 shell KHÔNG tới cụm: exit=-1 ")

Kết hợp với log sẵn có của DadbSimpleCastShell (tag SimpleCast: shell: / shell OK / shell FAIL), một lệnh adb logcat ClusterNavWidget:* SimpleCast:* là đủ kết luận trên xe.

D3 · Trạng thái trên card Nav (thay vì im lặng)

Lớp wiring mới NavClusterOp39Status(activity) (giữ MainActivity + NavClusterModeButtons gọn, và bảo toàn hợp đồng "no shell" của NavClusterModeButtons): bind() tìm view + gắn click nút test; refresh() đọc ClusterNavLaneWidget.status/detail → set text. Gọi refresh() từ MainActivity.refresh() (đã chạy mỗi 1s qua refresher). Chuỗi hiển thị qua Lang.t(vi,en).

D4 · Nút "Test cụm ngay"

fun selfTest(ctx, report: (Op39Status, detail:String) -> Unit) {
    io.execute {
        if (castEnabled) { report(GATED_CAST, "Cast đang bật — tắt để test nav-only"); return }
        val r = runCatching { coordinator.executeShell(CMD) }.getOrNull()   // bỏ qua debounce + centerMode
        if (r?.success == true) report(ASSERTED, "đã gửi op39 (exit=0)")
        else report(SHELL_UNREACHABLE, r?.let{"exit=${it.exitCode} ${it.stderr}"} ?: "shell không phản hồi")
    }
}

Nút gọi selfTest; callback marshal về UI thread bằng activity.runOnUiThread { Toast … } + cập nhật luôn dòng trạng thái D3. Tôn trọng gate Cast (không đánh nhau với track Cast) nhưng bỏ qua yêu cầu nav-active/centerMode/debounce vì đây là hành động test tường minh của người dùng. Overlay chỉ có nội dung khi có nav sống — Toast nói rõ nó xác nhận đường giao, không phải hình.

Boundary shapes (đọc cả 2 đầu):
  • ClusterNavLaneWidget.status/detail (producer, @Volatile) ↔ NavClusterOp39Status.refresh() (consumer): enum + String, đọc thuần, không nullable.
  • selfTest callback (Op39Status, String) ↔ MainActivity lambda → runOnUiThread: gọi off-main, phải marshal.
  • coordinator.executeShell(cmd): ShellResult (core) — success = exitCode==0; dadb fail → exitCode=-1, stderr=msg (không throw). Consumer chỉ đọc success/exitCode/stderr.
  • Layout ids mới (txt_cluster_op39_status, btn_nav_cluster_test) phải có ở cả layout/ và layout-w960dp/ để findViewById không null trên cả 2 cấu hình.
