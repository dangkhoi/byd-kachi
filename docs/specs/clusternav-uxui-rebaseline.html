02

Context & audit

Current strengths

  • Main screen already uses large 56dp actions and text status in addition to color.
  • Bubble provides quick access while another app is open.
  • Per-app scale, presets and live debounce solve real vehicle-specific needs.
  • Diagnostics can capture without external Wi‑Fi/ADB.

Current structural problem

  • One long page exposes navigation, GPS, Cast and troubleshooting together.
  • Cast screen combines driving controls, policy, app library, geometry, profile, update and logs.
  • Multiple entry points infer state from RAM flags and present different actions.
  • Documentation and current bubble/long-press behavior already disagree.

Navigation behavior

  • Cluster lane and HUD share source/session but retain separate output status.
  • HUD toggle is visible, not hidden inside troubleshooting.
  • GPS Dead Reckon is absent under the REMOVE decision; no mock-location setup or green assistance claim remains.

Producer↔consumer contract tests must compare every field, nullable/reason enum and freshness transition. U2–U6/U23 bind to this model; adding an output/source state must fail exhaustiveness gates until rendered and action-mapped.

Pipeline-A producer is prerequisite to screens: NavigationSessionCoordinator (or equivalently named owner) owns source identity, session ID, freshness, process rehydration and immutable frames/store. ClusterLaneAdapter and HudAdapter each own a bounded queue, executor, deadline, cache and error state; neither may call/reset the other. Whole-navigation Stop clears the shared session and both outputs; a per-output toggle affects only that adapter. The only output states are OFF | STARTING | EMITTING | DISPLAY_VERIFIED | STALE | FAULT(reason); EMITTING proves attempted delivery only, while DISPLAY_VERIFIED requires acknowledgement or independent observation. Contract tests cover every field/nullability/enum, restart rehydration, bidirectional block/throw/saturation and static no-Cast edges.

App manager

  • Searchable installed-app list; favorites are explicit and ordered.
  • Tapping a row opens details; Add/Remove is a labeled control, not the same tap as Cast.
  • Projection apps are automatically marked “Giữ phiên”. User overrides live under Advanced with consequences.
  • 0.72 field-execution amendment: app details also own two per-app presentation choices — Kiểu cụm (cong · giữ đồng hồ km/h ↔ thẳng · dùng hết khung) and Cỡ chữ trên cụm (DPI) with an explicit “theo mặc định của cụm” option. Both are preferences: changing them dispatches no Cast operation and they take effect on the next cast of that app. Casting never force-stops a target by default; when the gentle ladder cannot land the app, a prompt states that the next step kills the running session and only an explicit tap escalates. That prompt is never offered for CarPlay/Android Auto or a keep-session app.
  • 0.71 amendment (supersedes the earlier favorites-only radio): exactly one durable default app is chosen through distinct Set/Replace/Clear controls and may be any currently eligible launchable policy-supported app; favorites affect ordering and quick access only. Auto-cast is a separate Enable/Disable control over that one default, disabled on fresh install, and Enable requires the current versioned consequence disclosure plus explicit Accept. Cancel writes nothing, Revoke clears consent, and a newer disclosure version renders REVIEW_REQUIRED until re-accepted. Protection is presented as four typed classes — NORMAL, SYSTEM_PROJECTION, USER_KEEP_SESSION, UNKNOWN_PROTECTED — where system and unknown entries are visibly locked and unknown exports no Cast or destructive action. Row tap opens details only; Favorite, Cast, Set/Replace/Clear Default and protection are separate labeled controls; a stale default stays visibly unavailable with Clear/Replace guidance and is never silently substituted. See docs/specs/cluster-cast-v071-product-completion.html.

Bubble

  • Idle is one labeled ≥56dp Menu bubble. Any state/reason whose required StopDisposition=AVAILABLE expands into a docked two-action pill: labeled ≥64dp Stop + separate ≥56dp Menu. Every other disposition renders the exact non-mutating status defined below. No blind toggle, double-tap or hidden long press.
  • When StopDisposition=AVAILABLE, direct Stop sends the same typed intent as Cast control and must render STOP_REQUESTED within 500ms. REQUESTED/IN_PROGRESS cannot dispatch again; COMPLETED/UNAVAILABLE explains the terminal reason.
  • While Menu is open the overlay becomes focusable with deterministic focus order, Back/outside dismiss and restored flags on close. Accessibility label includes stable state and target.
  • Bubble renders the same CastUiState; it owns no state or retry policy.
  • 0.71 amendment — independent opt-in: Bubble desired-enabled is a presentation preference that is off on fresh install and when the legacy key is absent; only an explicitly present legacy true/false migrates. D7 — State ownership and regression isolation

  • Home renders two summaries in independent containers; failure to render one cannot substitute the other's state.
  • Feature flags are independent: nav_ui_v2 and cast_ui_v2. Rollback one pipeline without rolling back the other.
  • Shared visual components accept display data and callbacks only; they cannot import runtime singletons.
  • Legacy Cast sessions remain visibly legacy/read-only until safe migration; V2 UI never fabricates V2 recovery actions.

Binding lifecycle ownership

Views subscribe and render only. Activity, overlay and custom-view create/recreate/inflate paths dispatch zero pipeline mutation. They may request a read-only snapshot/subscription. Persisted opt-in automation (Bubble service, auto-cast, watchdog/reconcile) belongs to the relevant pipeline lifecycle coordinator, is deduplicated by durable intent/epoch, and appears as state; it is never synthesized by view creation. Legacy GPS auto-start is retired and must never be recreated by the V2 UI. U1 means “no operation synthesized by rendering,” not “suppress valid coordinator-owned automation.”
