02

Context

Đầu mối đã chứng minh: VietMap 3.3.4 chủ động gọi AppWidgetManager.updateAppWidget() để đẩy tốc độ hiện tại, speed limit, hai cảnh báo gần nhất và khoảng cách cảnh báo vào VMOnlySpeedLimitWidgetProvider và VMAlertWidgetProvider.

BLE self-loopback

Không có API Android được hỗ trợ để VietMap scan/connect GATT server của ClusterNav trên cùng adapter. Hướng này dừng.

Accessibility

Đọc được 0 km/h 50 và 100m + road, nhưng phụ thuộc cửa sổ VietMap còn accessible. User yêu cầu VietMap được chạy nền, nên không chọn.

AppWidgetHost

IPC hệ thống, cùng máy, không root, không sửa VietMap. Provider chủ động push dữ liệu kể cả khi UI VietMap không active — cần POC xác minh background freshness.

Ranh giới scope: POC này chỉ lấy dữ liệu, hiển thị trạng thái và chứng minh lifecycle nền. Chưa đẩy speed limit lên cluster/HUD, chưa thay SourceArbiter và không sửa pipeline Google Maps.
Approval gate: implementation chỉ bắt đầu sau approval out-of-band cho toàn bộ spec. Không lưu trạng thái approval trong tài liệu.

4.2 Binding flow

AllocateAppWidgetHost.allocateAppWidgetId()
→
Try bindbindAppWidgetIdIfAllowed()
→
User consentACTION_APPWIDGET_BIND if needed
Persistence rule: chỉ persist ID sau khi provider thực sự bound. Cancel/failure phải deleteAppWidgetId(). Hai provider bind tuần tự để result không nhập nhằng.
Self-grant trên head unit (đảo R12 remediation, chủ dự án chốt 2026-08-06). Đầu xe không có launcher/UI để hiện dialog ACTION_APPWIDGET_BIND, nên trước đây app hiện message bắt người dùng gõ tay adb shell appwidget grantbind — bất khả thi khi đang lái. App vốn đã là công cụ adb-mode (cài đặt đã hàm ý quyền loopback: Cast dùng pm install/wm/am, tự cập nhật dùng pm install), nên nó tự chạy appwidget grantbind --package com.byd.clusternav --user 0 qua LocalDeviceShell (uid shell 2000) rồi bindAppWidgetIdIfAllowed() lại một lần. Grant chỉ mở cho CHÍNH package này (không đụng app khác) và persist ở allowlist user 0. Chạy off-main; retry đúng MỘT lần; message thủ công giữ làm fallback cuối nếu loopback không tới được. Đường consent chính thống vẫn dùng khi có UI.

4.3 Lifecycle ownership

Start

  • NavNotificationListener.onListenerConnected() gọi bridge start.
  • Load persisted IDs, verify provider component, create host views.
  • AppWidgetHost.startListening().
  • Không phụ thuộc VietMap notification content.

Stop / recover

  • onListenerDisconnected() stop listening; RebindReceiver khôi phục.
  • Process restart recreate host từ IDs.
  • Package replaced / bad provider → Unavailable và yêu cầu rebind.
  • Không tự allocate ID lặp vô hạn.
POC assumption cần đo: AppWidgetHostView nội bộ, không hiển thị và không gắn window vẫn phải nhận/apply update trong process. Background test là exit gate, không phải giả định ship. Nếu framework bắt buộc attach view, chỉ được dùng container nội bộ 1×1 trong suốt, không lộ UI widget.

05

Tasks

T1 · Core

Typed model + parser

  • Create snapshot/freshness/reason contracts.
  • Parse numeric and distance widget text; reject sentinels and out-of-range values.
  • Unit tests for valid, stale, malformed and version-shape cases.
T2 · Host

Widget host and persistence

  • Implement custom AppWidgetHost/HostView callback.
  • Persist and validate two widget IDs.
  • Resolve remote view IDs dynamically by package/name.
  • Batch/debounce separate RemoteViews updates into one snapshot.
T3 · Binding

One-time consent UX

  • Enumerate exact providers.
  • Sequential allocate/bind flow with ACTION_APPWIDGET_BIND fallback.
  • Cancel, invalid ID, provider removed and rebind paths.
T4 · Runtime

Navigation-owned background lifecycle

  • Start/stop listening from NavNotificationListener.
  • Restore after process restart/rebind.
  • Fresh/stale/unavailable transitions without changing NavRepository output.
T5 · Diagnostics

Internal proof and target validation

  • Show binding state and parsed fields only; keep VietMap HostView internal/non-visible.
  • Emulator route test with VietMap foreground then background.
  • On-car bind/background/restart matrix.
T6 · Review

Scope and boundary review

  • Compare RemoteViews producer fields against parser field-by-field.
  • Run focused tests and build.
  • Senior review with no cluster-output expansion.
