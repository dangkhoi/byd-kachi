Cockpit UI Design System

Slug: ui-design-system · Framework theme @android:style/Theme.Material (always dark) · Trạng thái: Current

Cập nhật: 2026-09-05 · Mục đích: từ điển component dùng lại (@style/Cockpit.*) + token cho toàn bộ UI ClusterNav. Mọi màn mới phải lắp từ đây, không dựng widget mặc định lẻ.

Nguồn: app/src/main/res/values/{styles,themes,colors,dimens}.xml + app/src/main/res/drawable/*. App KHÔNG có AppCompat/Material3 — parent widget là @android:style/Widget.Material.* (đã xác minh public ở platform-37 public-final.xml).

1. Context

(VI) UI ClusterNav là "buồng lái" tối, luôn-tối. Trước đây các dropdown/Spinner/SeekBar còn mang look Material sáng mặc định (nền trắng, mũi tên xám) trông lạc lõng trên nền tối. Design system này (a) chuẩn hoá một bộ style dùng-lại có tên Cockpit.* tham chiếu token sẵn có, và (b) reskin toàn bộ Spinner + SeekBar qua theme + adapter + resource mới — không sửa hai layout bị byte-seal (activity_main.xml bản dọc + layout-w960dp).

(EN) The UI is an always-dark cockpit. Default Material spinners/seekbars still looked light-on-dark. This system standardizes a reusable Cockpit.* vocabulary bound to existing tokens, and re-skins every Spinner + the SeekBar via theme attrs + adapter item layouts + new drawables — with zero edits to the two byte-sealed layouts.

Ràng buộc (đã tôn trọng): không sửa res/layout/activity_main.xml · res/layout-w960dp/activity_main.xml · values/strings.xml (byte-sealed T11). Reskin đạt được ở tầng theme (android:spinnerStyle/seekBarStyle…) + adapter + drawable/layout mới ⇒ seal shasum không đổi (lần 17), không re-pin.

6. Reuse rules (bắt buộc)

  • Compose, đừng chế: UI mới PHẢI lắp từ @style/Cockpit.* + drawable dùng-chung (card_bg, btn_*, spinner_bg, popup_bg, pill_bg, segment_bg, tile_*).
  • Cấm widget mặc định lẻ: không dựng button/spinner/seekbar bằng look Material mặc định hay style một-lần. Spinner/SeekBar mới tự động đúng nhờ theme; button/switch/pill/segment → gắn style="@style/Cockpit.*".
  • Thiếu component → thêm vào design system TRƯỚC: nếu cần thứ chưa có, thêm style mới vào styles.xml (kèm comment) + drawable/token nếu cần, rồi mới dùng. Không đẻ style rời trong layout.
  • Token là nguồn sự thật: chỉ tham chiếu tên màu/dimen; không hardcode hex/sp/dp trong style hay layout.
  • Không đụng layout byte-seal: activity_main.xml (2 bản) + strings.xml. Đổi diện mạo widget qua theme/adapter/resource mới (mẫu §4).
