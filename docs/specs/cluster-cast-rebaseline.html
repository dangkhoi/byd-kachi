Current architecture problem

Root architecture failure: “state” hiện là ba nguồn không đồng bộ. Các workflow tự quyết định khác nhau, rồi xoá cờ trong finally kể cả khi external state chưa sạch. Vì vậy app có thể báo idle trong khi cụm vẫn active/orphaned.
Owner-approved policy amendment · 2026-07-25: Đăng Khôi approved removing all PARKED-based feature gating. Interaction context is diagnostic-only and cannot change actions or recovery eligibility. Destructive recovery remains guarded by known ownership/session loss, explicit consequence confirmation, synchronous journal/epoch fencing, one-attempt budget and verified postconditions. This amendment supersedes every older PARKED predicate in this document.
Candidate 0.70 manual cold-intent amendment · 2026-07-25: On the exact supported Seal DL3 profile, an otherwise pristine V2 envelope with no named cluster display is an actionable COLD_PRISTINE presentation state, not a recovery failure and not a durable stable state. One explicit user CAST intent validates the selected target, journals and verifies BOOTSTRAP, reaches durable IDLE_VERIFIED, then freshly replans and journals CAST without a second click. Retry is reserved for an actual bounded transport/recovery failure. Warm CAST/SWITCH never emits the cold create sequence or recreates the display. Cases 1–3 and 31 are interpreted by this rule; detailed acceptance and implementation boundaries live in cluster-cast-v070-manual-cold-intent.html.

Clean replacement design

D0 — Exactly two independent runtime pipelines

navigation pipelinecast pipelineseparate output adapter

Permitted inside Pipeline A

  • Cluster Nav and HUD share notification source, source arbitration, parsed NavState and navigation-session start/stop.
  • They have separate output adapters; HUD failure/toggle cannot backpressure or disable the Cluster lane.
  • Navigation stop may clear both navigation outputs because they represent the same session.

Forbidden across A ↔ B

  • No direct start/stop/reset/recovery calls in either direction.
  • No shared mutable state, preference-as-runtime-state, executor, lock, journal, epoch, cancellation, queue, retry budget or watchdog.
  • No Cast status gates Nav/HUD; no navigation state triggers or compensates Cast. A source app package may coincide with the cast target, but identity coincidence creates no control dependency.
Independence contract: “independent” means functional, orchestration and owned-resource failure isolation. Adapter exceptions, pipeline-owned queue saturation and owned-executor blockage may not propagate. Main-thread ANR, host-process death, platform/adbd failure and device reboot are shared fault domains unless process separation is separately approved; for those rows the binding guarantee is non-corruption and independent rehydration, not uninterrupted continuity. Shared code is limited to pure command encoding/formatting, immutable visual tokens and build provenance. Each pipeline owns its live gateway, executor, timeout, cache, cancellation and lifecycle.

D4 — Unified command policy

Classification is typed and closed: NORMAL; PROJECTION_SINK (behavior/component evidence); KEEP_SESSION (user-protected normal app); or UNKNOWN_PROTECTED. Only NORMAL may use force-stop/clear-task during ordinary cast/switch/Stop. All protected classes use resume/occlude/gentle-return and fail closed. A planner snapshot records classification evidence so a package cannot change class mid-operation. The sole exception is a new recovery operation with typed eligibility DISCONNECTED_SINK_RECOVERY_ELIGIBLE: owner identity is Known, phone/session connection is independently observed absent, two stable WM+AM samples confirm residue/orphan, no continuity remains to preserve, user or automatic disconnect policy explicitly requested recovery, and its ledger records a one-attempt fence. Eligibility is re-observed and persisted for that recovery epoch; Interaction context is not a recovery predicate and never changes action availability. Every destructive disconnected-sink/orphan heal instead requires explicit consequence confirmation plus all owner/session/two-sample/one-attempt predicates. Ordinary Stop-intent persistence remains preemptive. If any predicate is Unknown, force-stop is forbidden.

D5 — Stop is preemptive, but never a concurrent mutator

  • Một normal-operation owner với durable monotonic epoch; mỗi plan/step mang operationId + epoch + gatewayGeneration và kiểm trước/after I/O.
  • Stop synchronously persists stopRequested=true, bumps durable epoch, rejects new cast/geometry intents, closes the active ShellGateway, and cancels/fences the old worker.
  • Closing a socket is not proof that the remote shell command did not execute. The emergency lane may open a fresh gateway for read-only observation immediately, but it may mutate only after one of: (a) active command returns and releases the mutation lease; (b) gateway supplies a tested termination acknowledgement and post-close observation determines the command effect; or (c) the old command had been classified read-only. No two mutating commands may overlap.
  • If mutation ownership cannot be proven within the Stop acquisition deadline: persist RECOVERY_PENDING(reason=UNKNOWN_IN_FLIGHT_EFFECT), keep cover/teardown commands unissued, show “Stop requested—waiting for safe recovery”, and let watchdog re-observe with a finite budget. This is safer than racing a second executor.
  • After ownership is safe, Stop re-plans from fresh observation; it may launch the minimal opaque ClusterCover, but only as a normal journaled target with landed/opaque/occlusion gates. Cover failure means no gentle return and no teardown.
  • Binding initial deadlines: connect 4s; normal shell 10s; dumpsys 15s; mutation-lease acquisition 5s; switch 30s; cold cast 60s; one compensation attempt 20s. Stop intent must be durably persisted and UI must reach STOP_REQUESTED within 500ms of the user action. Phase 2 cannot enable V2 mutation until blocked-close tests prove these configured bounds and the 5s acquisition miss deterministically reaches RECOVERY_PENDING. Bounds may change only through measured evidence + spec update; deadlines always produce a terminal durable state, never replacement-thread growth.

D7 — UI contract

UI render từ immutable CastUiState, không đọc trực tiếp casting. It must distinguish ACTIVE_VERIFIED, ACTIVE_DEGRADED(residue, geometryLimited), STOP_REQUESTED, RECOVERY_PENDING(reason, nextSafeAction) và MANUAL_REQUIRED; never render degraded/recovery as “off”. Actions: Cast, Stop now, Try recovery, Retry, Choose another app. Mỗi action có operation ID; second selection in flight uses one durable latest intent, executes only after a stable point, and Stop always supersedes it. The UI presents exactly two subsystem statuses: Navigation (Cluster Nav + HUD) and Cluster Cast. CastCoordinator must have no import/control edge to ClusterBroadcaster/NavRepository/NavState; the navigation pipeline must have no import/control edge to CastCoordinator or its journal. Neither side may call the other's start/stop/reset/recovery API or share executor, lock, queue, watchdog, cancellation or durable state.

Technology validation: không thêm framework/dependency mới trong phase đầu. Official Android guidance (Context7: Android Developers) xác nhận in-memory flags không đủ cho process death và UI nên render observable state; cancellation phải được rethrow/handled explicitly. Journal dùng platform android.util.AtomicFile (API 17, phù hợp Android 10): official API guarantees complete write + sync before rename but explicitly requires caller-owned mutual exclusion. AOSP WM internals không có coverage đáng tin trong Context7, nên command safety tiếp tục dựa trên AOSP 10 source + on-car gates.
