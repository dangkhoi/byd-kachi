3Requirements

  • R1 — Discovery: Trên xe, xác định value↔menu map thật cho CẢ 4 mode (Đơn giản/Màn hình nhỏ/Toàn màn hình/OFF) bằng readback (OEM tự khai số), hết đoán. Gồm id mới 0x4C10E040 EASY_NAVI.

  • R3 — Render: Sau khi mở khoá + set đúng value "Đơn giản", cụm phải lên Giữa + ETA ổn định khi GMaps đang dẫn (không phải 1-shot).
  • R4 — Persist: App tự re-assert unlock + mode lúc boot / bật Nav+HUD, để reboot không làm mất nữa (giống fix self-grant accessibility 1.18).
  • R5 — 4-mode selector đúng: Selector trong app map đúng 4 value đã đo (R1); mỗi mode render đúng layout; OFF tắt centre.
  • R6: Off-car build xanh (JVM suite + signed assembleRelease, không surface vehicleTest).

4.4 Candidate matrix — test 4 mode on-car

Chia 2 lớp: Discovery (không cần build APK) trước, rồi Fix build sau khi có số.

Candidate A — Discovery probe (ưu tiên, chạy trước) ready

Dùng scripts/vehicle/nav-screen-mode-probe.sh (đã enhance kỳ này: thêm 0x4C10E040 EASY_NAVI vào readback + sweep). navopen sẵn ở /data/local/tmp/navopen.jar (uid shell — proven).

# B1. TRƯỚC KHI ghi gì: boot sạch → mở Cài đặt "Nav trên cụm" → menu xám hay chọn được? (chụp)
# B2. READBACK (OEM tự khai số cho 4 mode) — CHỈ chạy được khi menu ĐÃ hết xám:
VEH=<vehicle-ip>:5555 MODE=readback bash scripts/vehicle/nav-screen-mode-probe.sh
#   → tự tay chọn Đơn giản → Nhỏ → Toàn → OFF; script readback 015/01D/03A/040 mỗi lần
#   → nav-mode-probe/value-map.txt  = R1
# B3. SWEEP (đối chiếu, khi menu vẫn xám cũng chạy được): ghi 015=0..7, combo 015×01D, easy_navi=0..3
VEH=<vehicle-ip>:5555 MODE=sweep bash scripts/vehicle/nav-screen-mode-probe.sh

Candidate B — Unlock sequence (nếu menu vẫn xám) mò

Thứ tự thử (sau MỖI bước MỞ Cài đặt xem menu hết xám chưa — theo oncar-handoff-2026-08-14.md §A1–A3):

  1. navopen demo OPEN (status2 + screen3 + 1 frame).
  2. Bơm broadcast "đang dẫn" TRƯỚC (AUTONAVI KEY_TYPE 10001) rồi mới setraw 015.
  3. Sweep 015 = 0..5 + combo 01D=1 & 03A=1 & 015=3 + MỚI: 040 (EASY_NAVI) = 0..3.
Giả thuyết mới kỳ này
Menu bị cắt có thể mở bằng 0x4C10E040 EASY_NAVI (chưa từng thử) hoặc tổ hợp có 040 — vì tên "EASY_NAVI" khớp "Đơn giản". Ưu tiên test 040 trong Candidate B.

Candidate B2 — ICarHudService enable-API (RE-found kỳ này, ƯU TIÊN) mới

[RE:com.byd.car.feature.vision.ICarHudService] — binder service (BYD Car SDK) có API bật/tắt cấp cao hơn HAL thô, và ĐỌC được (khác id HAL 0x4C10E015 SET-only trả −10011):

7Open Questions

  • Q1: Boot sạch → menu OEM mặc định xám hay chọn được? (dữ liệu quyết định C-3 có cần re-assert mỗi boot không.)
  • Q2: Chuỗi mở khoá thật là gì? (015 đơn thuần đã FAIL post-reboot → nghi 040 EASY_NAVI hoặc broadcast-first hoặc tổ hợp.)
  • Q3: Mode là 1 value hay tổ hợp? (quyết định C-2.)
  • Q4: App-uid (BydPermissionBypassContext) có ghi render được không, hay chỉ uid-shell (navopen) → cần dadb loopback (C-3)?
  • Q5: Menu re-select thủ công trong Cài đặt có persist qua reboot không (nếu có, C-3 chỉ cần nhắc user, không cần tự ghi)?
  • Q6 (mới): ICarHudService có trong servicemanager (gọi service call được) hay chỉ SPI-bound (cần BYD Car SDK trong diagnostic build)? isNavigationMapEnabled() trước/sau reboot trả gì?
