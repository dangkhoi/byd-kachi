Context

Luồng Cast đang chạy = simplified: SimpleCastCoordinator (core) + FloatingBubbleService/BubbleActionDispatcher (app) + state SimpleCastState (Off/Idle/CastingFull/CastingSplit). Geometry per-app lưu qua SimpleCastPrefs theo profile key: FULL = <pkg>; split = <pkg>__L<pct>/__R<pct>. Density áp bằng wm density -d 1.

Ràng buộc phần cứng (A10): wm density là display-global — cả cụm chỉ có MỘT giá trị density tại một thời điểm. KHÔNG thể đặt trái=240 và phải=180 đồng thời (last-write-wins). Vì vậy "lưu DPI 2 màn" = lưu per-profile + áp lại khi re-cast, nhưng vật lý vẫn là 1 giá trị cho cả cụm. DPI per-side thực sự độc lập cần per-task scaling (ngoài scope).

Design

#3 · Nút nổi trái/phải — toggle (return-if-occupied else cast)

pure decisioncoordinator intent

Thêm hàm thuần BubbleGesturePlanner.slotOutcome(state, side) → RETURN|CAST (RETURN chỉ khi state is CastingSplit và nửa đó != null). BubbleActionDispatcher.onCastSlot dùng nó: RETURN → dispatch(Stop(side)); CAST → detectForeground → dispatch(CastSlot(fg, side)). Đây chính là logic nút zone trong app (MainActivityCastController.setupZoneButtons) — nay dùng chung cho cả nút nổi.

#1 · Resize không lưu — regression ở nhánh "adopt"

Trong SimpleCastCoordinator.handleCastFull, khi app đã ở sẵn trên cụm:

// TRƯỚC (bug): dùng NORMAL_DEFAULT + return TRƯỚC applySavedProfile → mất size đã lưu
if (geometry.isAppOnDisplay(pkg, displayId)) {
    setState(CastingFull(pkg, appType, DisplayConfig.forAppType(appType))); return
}
// SAU (fix): resolve config đã lưu + restore bounds/DPI
if (geometry.isAppOnDisplay(pkg, displayId)) {
    val adoptConfig = configurator.resolveConfig(pkg, appType, prefs)
    setState(CastingFull(pkg, appType, adoptConfig))
    if (appType == NORMAL) geometry.applySavedProfile(pkg, CastProfile.FULL)
    return
}

Phụ (đã sửa): CastDensityControl.saveForPkg/saveForProfile khi seed từ NORMAL_DEFAULT (bounds full 1920×720) khiến một thay-đổi-DPI-thuần đóng dấu bounds full lên slot split → re-cast phóng slot full, hỏng layout. Fix: seed NORMAL_DEFAULT.copy(bounds = null) cho các ghi density-only.

#2 · DPI mặc định 240 + split persistence

Không có literal "360" — đó là density gốc của panel mà wm density reset khôi phục; default cast là chuỗi "reset". Đổi mặc định: NORMAL_DEFAULT.density = "240" (một điểm duy nhất; CARPLAY/ANDROID_AUTO KHÔNG đổi vì dùng default param "reset"). Từ đó openProjection (apply NORMAL_DEFAULT), resolveConfig (NORMAL default), và nhánh adopt đều lấy 240. Split per-side DPI đã lưu+restore sẵn qua setDensitySplit → CastDensityControl.setForSplit (lưu 2 profile L/R) + applySavedProfile; nay không còn bị hỏng bởi bug bounds-stamping, và nhánh adopt (#1) khôi phục cả density.

Boundary shapes:
  • DisplayConfig.density: String ("reset" | số). Default param GIỮ "reset"; chỉ NORMAL_DEFAULT = "240". CP/AA configs không set density → giữ "reset".
  • Profile keys KHÔNG đổi (FULL=<pkg>; split=__L/R<pct>) — backward-compat.
  • slotOutcome(state, side) ↔ onCastSlot: enum RETURN/CAST; RETURN chỉ khi CastingSplit + nửa occupied.
  • Persist ONLY on shell success (R6) — giữ nguyên.
